All times start at the same parent timestamp, just before requesting both frames. Requests are near-concurrent, not exactly simultaneous. Launch order alternates on each run. No runtime is preloaded behind a ready barrier.

What these numbers mean

Document response is the iframe HTML response end. Main payload received is the last response end of the declared runtime payloads: MoonBit JavaScript + font; Rust JavaScript bindings + WASM (including its embedded fonts). Host scripts and worker dependencies are outside that payload endpoint; resource receipt does not prove compilation or rendering. Runtime signals use different endpoints and must not be ranked as equivalent render times.

Normal browser cache is allowed and is not cleared. Reload changes the document URL only; runtime asset URLs stay stable. Browser/CDN caches, compiled-code caches, parallel contention, GPU and connection warm-up are uncontrolled. Repeat runs are informal observations, not cold-start results.

First presented frame: unavailable for both. Canvas creation and returned draw calls do not verify screen presentation. Watch the panes for the practical visual result; no render-speed winner is claimed.
