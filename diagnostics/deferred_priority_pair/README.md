# Flat deferred-priority native pair

This new bounded diagnostic maps actual Rust per-box paint-entry callbacks to
actual core Quad command emission order and genuine layout bounds. It is not a
Rust scene-primitive dump, callback equality proof, raster test, or full popover.
The 16-case corpus and all eleven approved Rust oracle files remain unchanged.

## Frozen comparison

`comparison-policy.json` was frozen before candidate execution, SHA256
`ab397c1604af04c65f25b45ea3b96a03d3d4cb318e7a246cc9ccae1220d601ca`.
`control-policy.json` fixes exact mismatch witnesses before candidate execution,
SHA256 `6a8bde926ce504e1b8a360722de738e5dde9f29efd68293afc7c8f2e6d6bdd26`.
Every raw frame is retained and validated. Operation-final frames are compared,
using the preceding observed frame for input operations without redraws; redraw
counts are never equated. IDs, order and masks are exact. Numeric allowances are
fixed at 2^-10 logical px and 2^-10 physical pixels, inherited from the approved
bounded Rust oracle. No fitted tolerance or output normalization is permitted. Effective masks are
intersections of actually emitted clip stacks only. An absent stack is retained
as null and fails the required paired mask check; viewport clipping is never
invented as an observation. Candidate-only hit checks remain separate.

The candidate creates the authored ordinary boxes and each three-box subtree
through the actual core layout API. Explicit nonpainted reference/positioning
helpers adapt the restricted `anchored_after` shape; helper nodes are retained
with their actual IDs/parents/bounds and have no Rust callback counterpart.
Whole-subtree priority sorting occurs only in production core. The adapter does
not sort, synthesize per-node lifecycle callbacks, or inject final rectangles.
Transparent boxes retain zero-alpha backgrounds and actual Quad commands.

## Explicit observation gaps

All actual Rust request-layout/prepaint/paint entry and return records remain
in the baseline. Core tree iteration is used only for geometry and lineage.
The core has no corresponding per-node lifecycle callback API, so lifecycle
callback parity is always unestablished.

All 484 original Rust mouse-down callbacks remain available. Each candidate
input operation retains actual hit_test, dispatch_input, dispatch_input_with
visitation and closure invocation records for both down and up. The report
presents these alongside the actual Rust callback list. GPUI reverse-prepaint
hitbox occlusion and reverse-paint multi-listener propagation differ from the
preserved core topmost reverse-paint hit and structural capture/bubble routing.
Transparent, occluding and propagation-stopping configurations remain diagnostic
qualifiers. `input_parity_established` is false even when targets happen to agree.

## Evidence and gates

The profile must contain an independently reviewed exact published core commit
and tree before the source-bound runner will execute. Native source, selected
Git objects, staged package inputs, compiler/runtime bytes, exact direct-native
build plan, generated objects, executed ELF, run token and input are retained and
reopened independently. The original Rust approval remains explicitly labeled
public fa0c848e / CI 7dcd5510 / tree e9ccfbb2, artifact 12098386453; it is not
relabeled as a later-head run. Dedicated CI freshly executes all unchanged Rust
observers for the pair's own selected suite head.

Before any compiled production control, reopen the ordinary pair plus same-final-
core original 24-case anchor, separate 2-case fractional viewport, and 88-case
margin regressions. The original anchor observer needs only the retained exact
staging-only exhaustive Paint abort arm; its original source is unchanged and
its original compilation rejection is retained. Margin observer bytes are
unchanged. Wrong-priority, unstable-tie and subtree-interleaving controls must
compile and execute successfully, pass strict transport and structural
validation, then fail their predeclared paint-order witnesses. Compiler,
timeout, runtime, malformed transport and unrelated failures are never kills.

Separate copied/rehashed provenance corruptions test forensic rejection. They
are not executed engine mutations. Original evidence is never edited. Retained
copies keep their actual historical execution roots.

Run `python3 -m unittest discover -s tests -p test_deferred_priority_pair.py -v`
for synthetic checker/source tests only. Actual native pair, same-core regression,
production-control and copied-forensic runs belong to
`.github/workflows/deferred-priority-native-pair.yml`. No passing native claim is
made by source preparation or synthetic tests.

Production source selection is dynamic across all non-test `.mbt` and `moon.pkg`
files in the four compiled packages, including `container_query.mbt` and
`layout_bounds.mbt`. Before compilation, the complete filesystem inventory and
bytes must equal the selected Git blobs. The published
`element/pkg.generated.mbti` is retained separately as noncompiled API context;
the real compiler-consumed generated `.mi`, `.core`, objects and ELF are bound by
the exact native build plan. Rehashed alternate API/source bytes cannot satisfy
the independently selected Git binding.
